# Module 41-8: Dynamic Profile Page (স্টাডি ও ইন্টারভিউ নোট)

---

## ১. ক্লাসের মূল উদ্দেশ্য (Key Objectives)
1. **প্রোফাইল পেজ তৈরি (`/profile`):** লগইন করা ইউজারের বিস্তারিত তথ্য প্রদর্শনের জন্য একটি আকর্ষণীয় ও রেসপনসিভ ড্যাশবোর্ড UI তৈরি করা।
2. **সার্ভার সাইডে সেশন ভ্যালিডেশন:** Next.js Server Component-এ `auth.api.getSession({ headers: await headers() })` ব্যবহার করে ডাটা ফেচ করা।
3. **আন-অথেনটিকেটেড ইউজার রিডাইরেক্ট:** লগইন ছাড়া কেউ `/profile` পেজে আসার চেষ্টা করলে তাকে স্বয়ংক্রিয়ভাবে সার্ভার লেভেলেই `/signin` পেজে রিডাইরেক্ট করা।
4. **ডাইনামিক ইউজার ডাটা ডিসপ্লে:** ইউজারের নাম, ইমেইল, ছবি/অ্যাভাটার, ইউজার আইডি এবং বাংলায় ফরম্যাট করা যোগদানের তারিখ (`toLocaleDateString("bn-BD")`) প্রদর্শন করা।
5. **ইন্টারেক্টিভ সাইন আউট:** প্রোফাইল পেজ থেকেও ব্যবহারকারী যেন এক ক্লিকে সাইন আউট হতে পারে তার ব্যবস্থা করা।

## ২. আর্কিটেকচারাল ডিসিশন: Server Component বনাম Client Component

| বিষয় | Server Component (`auth.api.getSession`) | Client Component (`useSession`) |
| :--- | :--- | :--- |
| **লোডিং স্টেট (CLS)** | কোনো Layout Shift নেই; পেজ লোড হওয়ার আগেই ডাটা তৈরি থাকে | `isPending` হ্যান্ডেল করতে হয়, সাময়িক ফ্ল্যাশ হতে পারে |
| **সিকিউরিটি ও রিডাইরেক্ট** | সার্ভারেই চেক হয়ে যায়; আন-অথেনটিকেটেড ইউজার কোনো HTML দেখতে পায় না | ব্রাউজারে রেন্ডার হওয়ার পর রিডাইরেক্ট হয় |
| **বান্ডেল সাইজ** | ব্রাউজারে অতিরিক্ত জাভাস্ক্রিপ্ট যায় না (Zero JS) | ক্লায়েন্ট বান্ডেলে হুক ও কোড লোড হয় |
| **ইন্টারভিউ স্ট্যান্ডার্ড** | **Next.js 15 App Router Best Practice (Recommended)** | সাধারণ ইন্টারঅ্যাক্টিভ কম্পোনেন্টের জন্য ভালো |

## ৩. কোড ও লাইন-বাই-লাইন বিস্তারিত ব্যাখ্যা

### ফাইল: `src/app/profile/page.tsx`

```tsx
1: import Image from "next/image";
2: import Link from "next/link";
3: import { redirect } from "next/navigation";
4: import { headers } from "next/headers";
5: import { auth } from "@/lib/auth";
6: import SignOutButton from "./SignOutButton";
```
- **ব্যাখ্যা:**
  - `redirect`: সার্ভার সাইড থেকে ব্যবহারকারীকে অন্য রুটে পাঠিয়ে দেওয়ার জন্য Next.js মেথড।
  - `headers`: ইনকামিং HTTP রিকোয়েস্টের হেডার (কুকিসহ) পড়ার জন্য Next.js 15 ফাংশন।
  - `auth`: Better Auth-এর সার্ভার ইনস্ট্যান্স।
  - `SignOutButton`: সাইনআউট পরিচালনার জন্য আলাদা ক্লায়েন্ট কম্পোনেন্ট।

```tsx
8: export default async function ProfilePage() {
9:   // সার্ভার সাইডে সেশন ডাটা সংগ্রহ করা (Next.js 15 + Better Auth)
10:   const session = await auth.api.getSession({
11:     headers: await headers(),
12:   });
```
- **ব্যাখ্যা (সার্ভার সেশন ফেচ):**
  - Next.js 15-এ `headers()` একটি অ্যাসিনক্রোনাস ফাংশন, তাই `await headers()` ব্যবহার করতে হয়।
  - Better Auth কুকি থেকে সেশন টোকেন ডিক্রিপ্ট করে ডাটাবেজ থেকে ইউজারের সম্পূর্ণ রেকর্ড নিয়ে আসে।

```tsx
14:   // যদি ইউজার লগইন না থাকে, তবে সরাসরি সাইন ইন পেজে পাঠিয়ে দেওয়া হবে
15:   if (!session?.user) {
16:     redirect("/signin");
17:   }
```
- **ব্যাখ্যা (সার্ভার প্রটেকশন):**
  - যদি কোনো ইউজার লগইন না থাকে, তবে সার্ভার পেজের HTML জেনারেটই করবে না। ব্রাউজারে সাথে সাথে HTTP 307 Redirect পাঠিয়ে `/signin`-এ পাঠিয়ে দেবে।

```tsx

79:       year: "numeric",
```

## ৪. SCIC ও টেকনিক্যাল ইন্টারভিউ প্রশ্নাবলী (Interview Q&A)

### প্রশ্ন ১: সার্ভার কম্পোনেন্টে Better Auth দিয়ে কীভাবে সেশন চেক করতে হয়?
> **উত্তর:** `auth.api.getSession({ headers: await headers() })` মেথড ব্যবহার করে। এটি ইনকামিং রিকোয়েস্টের কুকি হেডার পড়ে সার্ভার লেভেলেই সেশন যাচাই করে।

### প্রশ্ন ২: Next.js 15-এ `headers()` ব্যবহারে কী পরিবর্তন এসেছে?
> **উত্তর:** Next.js 15 থেকে রিকোয়েস্ট-স্পেসিফিক API (যেমন `headers()`, `cookies()`, `params`, `searchParams`) অ্যাসিনক্রোনাস করা হয়েছে। তাই এদের সামনে অবশ্যই `await` ব্যবহার করতে হয় (যেমন: `await headers()`)।

### প্রশ্ন ৩: প্রোফাইল পেজের ভেতর সাইন আউট বাটনকে আলাদা ক্লায়েন্ট কম্পোনেন্ট কেন বানালাম?
> **উত্তর:** প্রোফাইল পেজটি সার্ভার কম্পোনেন্ট হওয়ায় এতে সরাসরি `onClick` ইভেন্ট হ্যান্ডলার কাজ করবে না। তাই Next.js-এর আর্কিটেকচার অনুযায়ী সাইন আউট বাটনটুকুকে আলাদা লিফ কম্পোনেন্ট (`SignOutButton.tsx`) বানিয়ে `"use client"` দেওয়া হয়েছে।
